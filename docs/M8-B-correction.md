# M8-B 更正：fill 并没有造出“一热一冷”，低命中来自总量超容

## 诊断（加了 `[bal]` 打印后一次跑就看清了）

`EXECUTOR_PLACEMENT=fill`、HOT=0.60、COLD=0.45，40 program × 1500 词 × heavy 0.7×3：

```
[bal] usage={'a': 0.0,   'b': 0.0}   hot=0.000 cold=0.000 moves=0   (开局)
[bal] usage={'a': 0.562, 'b': 0.540} hot=0.562 cold=0.540 moves=0   (跑到一半)
```

两个事实：

1. **fill 很快就把 b 也用上了**：a 卡到达 0.85 上限后新 program 溢出到 b，最后两卡需求比 **0.562 / 0.540**——基本持平。所以“fill 造出一热一冷”这个假设是错的。
2. **平衡器被 `cold > COLD` 正确挡住**：差值只有 0.022，远小于 `gap≥0.10`；这种情况下不动手是对的。

## 因此上一版结论要更正

| 曾经的说法 | 更正 |
|---|---|
| “放置质量是主要矛盾：85.7% vs 18.6%，差 67 pt” | **错**。两组负载大小不同：均匀档是 800 词（每卡 0.37），fill 档是 1500 词 + 70% 重尾×3（总需求 ≈125k+，单卡 114k）。18.6% 是**总量超容**的结果，不是不均的结果——两卡需求比几乎相等就已经说明问题不在放置 |
| “搬家轴没测成是因为部署漂移” | 部分对：漂移确实让三代 `[bal]` 打印缺失、掩盖了真相；但补上打印后看到的是**没有可平衡对象** |

## 那 A 轴空、B 轴也空，2×2 说明了什么

- **A（放置信号）在 0.37 负载下为空**：两种信号给出完全相同的 85.7%。
- **B（搬家）在这个负载区间没有作用对象**：要么两卡均衡（无事可做），要么总量超容（搬了也装不下）。
- 真正决定命中率的仍然是**总量 vs 容量**：0.37 → 85.7%；1.1 → 18.6%。这与 b71/b72 的“容量墙”结论一致。

## 唯一还值得测的一格

**人为 34/40 钉卡 + 总需求恰好压在 0.9 容量**（既不均、又装得下）：这是唯一能看出“搬 vs 不搬”的区间。此前用 `/seed` 做过一次（65.4% → 61.9%，负收益），但那是 TA 在环、且未重启引擎。要下定论需要：seed 倾斜 + 每格重启引擎 + 3 rep。

## 教训

- **`[bal]` 这类打印必须常驻**：它是唯一能区分“没触发”和“触发了但对象不对”的证据。
- **改结论前先看两卡的 usage 对比**：这轮如果早点打印，就不会把“超容”误判成“不均”。
