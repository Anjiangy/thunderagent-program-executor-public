# 曲线图：长前缀三档（同 pod、同引擎）

数据：`data/m6_curve.csv`（由 `data/m6_total_table.csv` 与 step2/step4 的跑次合并），绘图：`scripts/plot_m6_curve.py` → `data/m6_curve.png`。

横轴 = 热卡 KV 需求 ÷ 单卡容量（47,616 token）。只画长前缀（600/900 词）三档，因为短查询（40 词）的每轮时延由另一套 max_tokens 预算主导，混在同一根"负载轴"上会伪造趋势。

| 热卡负载 | 裸 TA | 重算交接 | KV 搬运 |
|---|---|---|---|
| 0.44（21k/47.6k） | **81.6%** / 0.363 s | 81.1% / **0.340 s** | 79.7% / 0.354 s |
| 0.75（36k） | 未跑（无 seed 入口） | 74.1% / 0.365 s | 75.2% / 0.432 s |
| 1.11（53k，超容） | 未跑 | **51.2%** / 0.473 s | 43.5% / 0.707 s |

读法：
- 命中率三条曲线都随负载单调下降；0.44 处 TA 与重算交接基本重合，1.11 处搬运比重算掉得更快。
- 时延上搬运始终更差（超容档 0.707 vs 0.473 s），因为它把一次 pull 放进被搬 program 的路径里。
